# Crimson Casebook

Build a complete, production-quality frontend for a Digital Forensics Investigation & Evidence Report Viewer.
This is a frontend-only module. Do not build a backend, database, API, authentication system, or server. The application will eventually consume a single report_data.json generated by another module. Use realistic mock data initially, but structure the code so the real JSON can be plugged in without changing the UI.
1. DESIGN GOAL
Create a premium professional forensic investigation dashboard using a strict RED + WHITE theme.
The interface should look like a real digital-forensics/evidence-analysis product used by investigators—not a generic admin dashboard.
Use:
White/light gray backgrounds
Deep red #B91C1C
Dark red #7F1D1D
Accent red #DC2626
Light red #FEF2F2
Dark text #111827
Gray borders #E5E7EB
Use modern typography, subtle shadows, clean spacing, professional icons, rounded cards, strong hierarchy, and restrained animations.
Avoid excessive gradients, excessive colors, glassmorphism, gaming-style UI, or unnecessary decorative elements.
2. TECHNOLOGY
Use:
React
TypeScript
Tailwind CSS
Lucide icons
Build reusable components and clean maintainable code.
Do NOT introduce unnecessary libraries or external services.
3. MAIN SCREEN
Create a polished dashboard with:
Header
Title:
DIGITAL FORENSICS REPORT
Subtitle:
Evidence Analysis & Investigation Timeline
Show:
Device ID
Evidence count
Entity count
Flag count
REPORT GENERATED status
Use a red accent line.
Search / Filter Bar
Large search field:
Search evidence...
Include:
Search icon
Clear Filters button
Result counter
Example:
Showing 12 of 35 evidence records
Search must work instantly on the client side.
4. AI SUMMARY
Place a prominent summary card below the header:
✦ AI-GENERATED CASE SUMMARY
Display overall_summary.
Use a light-red background and red border.
Include a small disclaimer:
AI-generated analysis — verify against source evidence.
AI-generated information must always look visually different from raw evidence.
5. MAIN LAYOUT
Desktop:
Left sidebar
Entities
Flags
Main area
Evidence Timeline
Use approximately 300px sidebar width and let the timeline occupy the remaining space.
On mobile, stack sections vertically.
6. ENTITY FILTERING
Create an attractive ENTITIES panel.
Each entity should show:
Name
Type
Number of linked records
Known contact when available
Example:
PERSON
John Smith
3 records
Clicking an entity must filter the timeline to only records whose IDs exist inside that entity's record_ids.
Selected entity gets a clear red active state.
Clicking it again removes the filter.
Provide a global:
Clear Filters
button.
7. FLAGS
Create a FLAGS / ANALYSIS section.
Each flag displays:
Warning icon
Reason
Source
Record IDs
Example:
⚠ ANALYSIS FLAG
Suspicious communication
Source: message
Records: [M001] [C001]
Use light-red warning cards.
Flags must clearly appear as analysis/derived information, NOT confirmed facts.
8. EVIDENCE TIMELINE
Create a beautiful chronological vertical timeline.
Sort by timestamp ascending.
Every item should contain:
Kind badge
Record ID
Timestamp
Headline
Detail
Supported kinds:
MESSAGE
CALL
AUDIO
IMAGE
Use clean red/white badges.
9. MESSAGE

Message badge

ID

10. CALL

Call badge

11. AUDIO
For audio records display:
Audio badge
Timestamp
Headline
Detail
Working audio player
Transcript

Below it show:
TRANSCRIPT

12. IMAGE
For image records display:
Image badge
Timestamp
Headline
Detail
Image thumbnail
Detected objects
OCR
AI caption
Detected Objects

[person 97%] [car 88%] [phone 91%]
Convert confidence values such as 0.97 → 97%.
OCR
Label:
OCR EXTRACTED TEXT
Display OCR separately from headline/detail.
AI Caption
Label:
✦ AI CAPTION — UNVERIFIED
Use a clearly different light-red AI card with red border and AI icon.
Include:
AI-generated content. Not verified.
NEVER merge the caption into headline, detail, OCR, or transcript.
13. CRITICAL AI/EVIDENCE VISUAL LANGUAGE
Make this distinction extremely obvious.
RAW / EXTRACTED EVIDENCE
Use:
White background
Neutral gray borders
Normal typography
Examples:
Messages
Calls
Transcripts
OCR
Object detections
AI / DERIVED INFORMATION
Use:
Light red background
Red border
AI/warning icon
Explicit label
Examples:
✦ AI-GENERATED CASE SUMMARY
✦ AI CAPTION — UNVERIFIED
⚠ ANALYSIS FLAG
An investigator should immediately understand what is evidence and what is AI-derived analysis.
14. SEARCH + FILTER LOGIC
Implement ONE centralized filtering system.
Maintain:
currentEntityFilter
currentSearchQuery

Search case-insensitively across:
headline
detail
transcript
ocr_text
Use substring matching.
A timeline item is visible only when:
entity matches AND search matches
Do not implement separate filtering systems.
Update the timeline instantly when filters change.
Show a useful empty state:
No evidence matches your current filters.
15. DATA CONTRACT
Build the frontend around this exact structure:
{
  "device_id": "DEV001",
  "overall_summary": "Overall case summary",
  "entities": [
    {
      "name": "John",
      "type": "person",
      "record_ids": ["M001", "C001"],
      "known_contact": "John Smith"
    }
  ],
  "flags": [
    {
      "reason": "Suspicious communication",
      "record_ids": ["M001"],
      "source": "message"
    }
  ],
  "timeline": [
    {
      "id": "M001",
      "kind": "message",
      "timestamp": "2026-08-24T10:30:00",
      "headline": "John → Alice",
      "detail": "Where are you?"
    },
    {
      "id": "MED002",
      "kind": "audio",
      "timestamp": "2026-08-24T11:00:00",
      "headline": "Recorded call",
      "detail": "Audio evidence",
      "transcript": "Transcript text",
      "media_uri": "data:audio/wav;base64,..."
    },
    {
      "id": "MED001",
      "kind": "image",
      "timestamp": "2026-08-24T12:00:00",
      "headline": "Image evidence",
      "detail": "Extracted image",
      "detected_objects": [
        {
          "label": "person",
          "confidence": 0.97
        }
      ],
      "ocr_text": "Meeting at 8 PM",
      "caption": "People standing near a vehicle",
      "caption_status": "unverified",
      "media_uri": "data:image/jpeg;base64,..."
    }
  ]
}

Handle missing/null fields gracefully. Never display null, undefined, or NaN.

Structure the data layer so the mock dataset can later be replaced by the real:
report_data.json
without redesigning the frontend.
Do NOT create any database/backend implementation.
FINAL RESULT
Deliver a polished, responsive Digital Forensics Evidence Investigation Dashboard with a strong red-and-white professional forensic identity.
All core interactions must work on the first generation:
Search
Entity filtering

Clear filters
Timeline sorting

Transcript display

AI summary

Analysis flags

Prioritize completing and polishing the core report viewer over adding extra features. Do not create unnecessary functionality that could consume development time or credits.
